# 設計決定

這裡記錄幾個**看起來像 bug、其實是刻意為之**的地方。動手改之前先看一眼，
免得把已經修好的問題又帶回來。

## 3D 地圖：高度是相對刻度，不是絕對值

縣市高度會跟著**當下這批資料的實際範圍**伸縮，不是固定對應 AQI 0–500。

理由是全台 AQI 平常都擠在 40–100。用絕對刻度換算，每個縣市的高度只差幾個
單位，放在 420×520 的地圖上等於一片平板，完全看不出差異。改成相對刻度之後，
同一批資料的高低差從 10.6 個單位變成 86。

代價是刻度會隨時間變動，所以畫面角落會標出目前高度對應的數值範圍
（例如「高度對應 AQI 44–112」）。絕對數值則由顏色分級與下方表格承載。

另外設有**最小跨距**：如果今天全台都是 60–63，純照實際範圍拉滿會把 3 點的
差距畫成一座山，反而誤導。跨距不足時會把範圍撐開，平靜的日子畫出來就真的
是平的。

震度則另外把下界釘在 0，因為震度 0 是「沒感覺」，是有意義的零點，不該跟著
當次地震的最小震度浮動。

## 3D 地圖：離島畫成平的

金門、澎湖、馬祖離本島很遠，投影後也只有十幾個單位大。擠到跟本島同高就變成
一片浮在海上的棕色板子，比資料本身還搶眼。

判斷依據是**地理位置而不是大小** —— 這樣本島上同樣小的嘉義市（9.2 單位）、
基隆市（14.2 單位）高度照常畫。離島的數值改由顏色分級與表格表達。

另外，投影後小於 1 個單位的碎塊直接不畫，那種環擠出來是一根沒有厚度的針。

## 3D 地圖：顏色要先解析 CSS 變數

`countyColor` 回傳的是 `'var(--aqi-moderate)'` 這種字串。2D 的 SVG 塞進 `fill`
由瀏覽器解析沒問題，但 `THREE.Color` 看不懂 `var()`，**解析失敗會靜靜 fallback
成白色**，整張地圖會變成同一片白而且不會報錯。

所以要先用 `getComputedStyle` 查出實際色碼再交給 Three.js。

## 3D 用簡化過的地圖資料，2D 用完整精度

完整精度的海岸線點太密，擠出 3D 時每一小段都變成朝向略有不同的牆，燈光照下去
會產生毛刺感。

但簡化門檻不能開太大：實測 `0.001` 會把馬祖 6 個部分**全部壓成 0 寬度**，擠出來
是一片薄板。現用 `0.0002`，馬祖與澎湖都保得住，點數仍只有完整精度的三分之一。

## 抓到 0 筆資料時不覆寫既有檔案

`writeJson` 是無條件覆寫。API 有時候會回 200 但內容是空的，照樣寫入等於把好資料
換成 `stations: []`，接著被 commit、部署上線，畫面直接變成「還沒有資料」。

這比回 500 更糟 —— 500 至少大聲失敗且什麼都不會動，空回應是安靜地把網站清空。
所以 0 筆時保留既有資料並讓該步驟失敗。

## 預渲染 HTML 裡的相對時間是建置當下凍結的

靜態 HTML 寫的「3 小時前」是建置那一刻算的。瀏覽器載入後前端會重算成正確值，
但**爬蟲與 JS 執行前的第一畫面看到的是舊值**，誤差上限等於重建間隔（3 小時）。

要根治得讓預渲染只輸出絕對時間、相對時間完全交給前端補。

## 客戶端用 createApp 而不是 hydrate

預渲染出來的是 2D 地圖（Node 裡畫不出 WebGL），實際要顯示的是 3D，硬走
hydration 一定對不起來。直接掛載讓 Vue 重畫整塊，換取不會有 hydration mismatch。

## 沒有 robots.txt

專案頁的 robots.txt 必須放在網域根目錄（`joe94113.github.io/robots.txt`）才會被
爬蟲讀取。放在這個 repo 只會變成 `/tw-environment-watch/robots.txt`，爬蟲不會理，
加了只是自我安慰。

sitemap 因此需要到 Google Search Console 手動提交。
